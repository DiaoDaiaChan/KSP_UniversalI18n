# KSP 通用 i18n Mod —— 总体设计（v0.2）

> **v0.2（2026-10-23）—— 已落实 01 §8 的 8 条约束，数字按 04/05 实测校正**
>
> 本版三处结构性变化：① 新增 §8.1「八条硬约束 → 落点对照表」，01 §8 的 8 条修订逐条有落点；
> ② 全文文本规模数字改为「按 mod 目录做语言并集」后的真实值（旧值见 §1 脚注）；
> ③ 新增 §5.5 覆盖率指标（hit / miss / stale），并把字体兜底提为 M0 第一优先级（§3.4）。
>
> 目标：不修改任何 mod 的 DLL 与配置，只在**渲染边界**和**配置加载边界**注入译文；
> 译文以「每 mod × 每语言一份数据包」的形式，经 CKAN / 在线仓库分发；
> 由 LLM 在 CI 中**增量**产出，并过自动化校验门禁后发布。
>
> 代号：UniversalI18n（UI18n）

## 2. 三个必须先纠正的前提

### 2.1 ModuleManager 不能 hook 任何东西

MM 只在 **GameDatabase 加载期**对 ConfigNode 做文本层面的增删改，没有运行时能力：
- 它拿不到 UI 字符串；
- 它拦不住任何方法；
- 它的替换结果会被写进 `ConfigNode`，进存档、进搜索索引、进排序。

所以原方案里「通过 MM 和 Harmony 来 hook 所有 mod 的实现」这句要拆开：
**Harmony 负责运行时拦截，MM 只负责配置文本注入**。二者不是并列的采集手段，而是两条不同的数据通道。

### 2.2 采集必须靠 IL 静态分析 + 运行时探针

- 静态（Mono.Cecil，KSP 自带 `Managed/Mono.Cecil.dll`）能拿到 **字面量 + 所在方法（= 上下文）**，
  这是全量覆盖的唯一来源；
- 动态（Harmony 探针）能拿到**拼接后的最终串**和「这个串真的会被显示」的确认。
  静态拿不到 `"Fuel: " + mass` 的结果，动态能。

两者合并才是完整语料。纯启发式筛字符串（本次实测 157,268 → 5,423）噪声太大，不可用作主路径。

### 2.3 优先级要倒过来：数据层 > Hook 层

| 方案 | 风险 | 见效 | 作者接受度 |
|---|---|---|---|
| 补 `zh-cn` 语言节点 | 极低（纯数据） | 立刻 | 高（可 PR 回原 mod） |
| 运行时覆盖 cfg 文本 | 低 | 快 | 中 |
| 渲染层 Hook | 中（可能破坏逻辑/性能） | 全覆盖 | 低（「你 hack 我」） |
| 字体兜底 | 中 | 决定可用性 | 高 |

先吃低垂果实，Hook 只做兜底。这也正好符合「优先本来就支持 i18n 的 mod」的原始意图。

## 3. 四层架构

```
L0  原生 key 填充      数据（MM 注入 Localization 节点）    8,975 key 里缺的 3,331
L1  配置文本覆盖       运行时 ConfigNode / 渲染层           6,745 条 cfg 文本
L2  渲染层拦截         Harmony（uGUI / TMP / IMGUI / 消息）  157,268 条字面量里筛出的 UI 串
L3  字体兜底           Harmony + 运行时 TMP font asset      CJK 豆腐块
```

### 3.1 L0 —— 原生 key 填充（最高优先级）

**原理**：KSP 的 `Localizer` 从 GameDatabase 里所有 `Localization` 节点构建字典，
节点下按语言分子节点，key 以 `#` 开头（`#autoLOC_`、`#LOC_xxx` 都行）。
MM 可以在这之前改写/新建这些节点 —— 本机 `GameData/RP1_Chinese/RP1_Chinese_Loc.cfg` 就是既有先例：

```
@Localization:AFTER[RP-1]
{
    en-us
    {
        #autoLOC_111558 = <color=orange>这个部件已经塞满辣…</color>
    }
}
```

**我们的产物**（每个 mod 一个文件，自动生成）：

```
@Localization:AFTER[AJE]
{
    zh-cn
    {
        #LOC_AJE_xxx = 译文
    }
}
```

**关键设计点 —— 写哪个语言节点？**

| 写入节点 | 效果 | 适用 |
|---|---|---|
| `zh-cn` | 只有玩家把游戏语言切成中文才生效 | 正确做法，默认 |
| `en-us` | 任何语言下都显示中文（覆盖英文） | 「强制汉化」开关，仅对只玩中文的用户 |

`RP1_Chinese_Loc.cfg` 用的是后者（注释写着「任何游戏语言下生效」）。我们要把两种模式都做出来，
默认走 `zh-cn`，提供 `ForceOverlay=true` 开关。**这是原方案里没提但会直接影响用户体验的分叉。**

**实现步骤**：
1. 扫描 `GameData/**/Localization/*.cfg` → 解析出 key → {lang → text}；
2. 与目标语言求差集 → 得到待翻译 key 集合（源文本 = `en-us` 节点的值）；
3. LLM 翻译（key 本身带语义，如 `#LOC_B9PartSwitch_ModuleB9PartSwitch_tank_volume`，翻译质量最高）；
4. 生成 MM patch，写入 `GameData/UI18n/Packs/<lang>/Native/<Mod>.cfg`（游戏内安装目录见 §6.1 与 [06 §6.4](06-工程骨架与构建.md)）。

**风险与退路**：若 MM 无法新建一个原本不存在的语言子节点（`@` 节点加子节点理论可以，需 M0 验证），
退路是插件在 `Startup.Instantly` 阶段直接往 `GameDatabase.Instance` 注入 `Localization` ConfigNode ——
实测日志显示 addon 实例化（22:20:32）早于 MM 处理 Localization 节点（22:20:47），时序上可行。

### 3.2 L1 —— 配置文本覆盖

覆盖对象：`PART.title/description/manufacturer`、`EXPERIMENT_DEFINITION`、
`TECHNODE`、`AGENT`、`STRATEGY`、`CONTRACT`、`MODULE` 的 `guiName`、`KerbalTrait` 等。

**决策：不做字面替换，只做显示层 + 搜索别名。**

理由：
- MM 字面替换是**加载期一次性**的，玩家在设置里切语言不会重算（除非重启），多语言用户直接坏掉；
- 改了 `title` 会污染存档引用、部件排序、按名查找的 mod 逻辑；
- 实测 `RP1_Chinese.cfg` 用 `@PART[*]:HAS[#name[...]] { @title = … }` 打了 286 KB 补丁，
  是可行的，但那是「一次性汉化补丁」的定位，不是「通用 i18n」的定位。

**我们的做法**：
- 显示：交给 L2（部件名最终也是 `Text.text` / `TMP_Text.text`）；
- 搜索：给 `AvailablePart.tags` **追加**中文关键词（tags 不进存档，安全），让中文能搜到；
- 可选「深度模式」：postfix `PartLoader` 完成后覆盖 `AvailablePart.title`，供按名匹配的 mod 使用，
  默认关闭，per-mod 白名单开启。

### 3.3 L2 —— 渲染层拦截（Harmony）

**实测确认可用的 patch 点**（来自本机 `RP1GUIZh` 的运行日志）：

| 目标 | 结果 |
|---|---|
| `UnityEngine.UI.Text.set_text` | 成功 |
| `UnityEngine.GUILayout.DoLabel` | 成功 |
| `UnityEngine.GUILayout.DoButton` | 成功 |
| `UnityEngine.GUILayout.DoRepeatButton` | 成功 |
| `UnityEngine.GUILayout.DoToggle` | 成功 |
| `UnityEngine.GUILayout.DoWindow` | 成功 |
| `UnityEngine.GUI.Label` | 成功 |
| `UnityEngine.GUI.Button` | 成功 |
| `UnityEngine.GUI.Toggle` | 成功 |
| `TMPro.TextMeshProUGUI.set_text` | **失败** |

失败原文（必须记住）：

```
System.ArgumentException: You can only patch implemented methods/constructors.
Patch the declared method System.Void TMPro.TMP_Text::set_text(System.String value) instead.
```

→ **TMP 要 patch 声明方法 `TMPro.TMP_Text.set_text`**，不能 patch `TextMeshProUGUI`。
`TMPro` 在 KSP 1.12.5 里编译进 `Assembly-CSharp.dll`（`Managed/` 下没有独立 TMP dll），
所以引用要用 `Assembly-CSharp.dll`。

**另一个实测经验**：`GUILayout.Label(string)` 的公开重载不直接可 patch，
要 patch 它的内部分发漏斗 `DoLabel(GUIContent, …)` —— 一处覆盖所有重载。这是省事的关键技巧。

**完整 patch 清单（建议）**：

```
uGUI     UnityEngine.UI.Text.set_text                     Prefix(ref string value)
         UnityEngine.UI.InputField.set_text               跳过（输入框，会破坏输入）
TMP      TMPro.TMP_Text.set_text                          Prefix(ref string value)  ← 声明方法
         TMP_InputField.set_text                          跳过
IMGUI    GUILayout.DoLabel / DoButton / DoRepeatButton / DoToggle / DoWindow
         GUI.Label / GUI.Button / GUI.Toggle / GUI.Box / GUI.Window / GUI.TextField
         GUILayout.Toolbar / GUI.SelectionGrid（string[] 重载，逐元素翻）
世界     UnityEngine.TextMesh.set_text（部件标签等世界文本）
消息     ScreenMessages.PostScreenMessage(string, …)      Prefix(ref string)
KSP      KSP.Localization.Localizer.Format / GetString    Postfix(ref string __result)
```

**硬约束（01 §8 落实；C1–C4 与 §8.1 对照表同号，S1–S2 是本节特有的实现级约束；违反即返工）**：

1. **C1 只改传进来的值副本**：`Prefix` 只允许改 `ref string value`，或**新建** `GUIContent` 后写回 `ref GUIContent` 参数。
   **绝不原地写 `content.text`** —— `GUIContent.Temp()` 返回 Unity 内部共享缓存实例，原地写会让全游戏共用对象永久变中文（D10）。
2. **C2 hook 层不准碰游戏**：禁止 `Harmony.Transpiler`（插件里 transpiler 方法数必须为 0）；
   禁止用 try/catch 包裹游戏方法体；禁止在 Prefix/Postfix 里调用任何游戏 API（`Localizer.*`、`PartLoader`、
   `InputLockManager`、反射玩法类型……）。try/catch **只允许出现在装 patch 的注册循环**里（逐 patch 捕获、失败计数）。
3. **C3 patch 目标必须在渲染层白名单内**：只接受 Unity 引擎/UI 类型（`UnityEngine.*`、`TMPro.TMP_Text` 的声明方法）；
   `RP0.*`、`KSP.SpaceCenterManagement`、`Contracts.*` 这类领域类型一律拒绝，由 CI 对 patch 清单做白名单校验（§8.2 C3）。
4. **C4 语言门控是启动期一次性判断**：`Localizer.CurrentLanguage` 不以 zh 开头且未开 `ForceOverride` 时，
   **一个 patch 都不装**（不是装了就 return），详见 §8.4。
5. **S1 失败只 log 不抛**：每个 patch 单独捕获，日志必须给出「目标 + 失败原因」，最后打印 `installed ok/total`。
6. **S2 A/B 类零 hook**：能靠 cfg 键化与 Localization 注入解决的文本，绝不用渲染 hook（05 §2、D23/D24）。

**为什么用 Prefix 而不是 Postfix**：setter 里赋值已经发生，Postfix 改参数回不到字段。
Prefix 用 `ref string value` 在赋值前替换。**副作用**：之后任何 `get_text` 读到的是译文，
若有 mod 用 `text.text` 做状态比较会翻车 —— 见第 10 节风险 3。

**上下文归属（决定要不要翻、用哪条译文）**：
- uGUI/TMP setter 的调用者就是 mod 代码 → 在 `[MethodImpl(NoInlining)]` 的 helper 里调
  `Assembly.GetCallingAssembly()`；注意 **`new StackTrace(2,false)` 实测 2,073 ns**（05 文档 §4），
  是普通查表的 100 倍，所以归属只能「首见串抓一次 + 全局预算 4,000」；
- IMGUI 的 `DoLabel` 调用者仍是 `UnityEngine.IMGUIModule` → 需 `new StackTrace(1, false)` 再往上走一帧，
  按 `RuntimeMethodHandle` 缓存解析结果（每个调用方法只解析一次）。

### 3.4 L3 —— 字体兜底（决定「能不能看」）

这是原方案完全没提、但**会直接导致项目失败**的一层：
mod 自带 TMP font asset 里没有汉字 → 全部豆腐块。本机 `GameData` 里只有
ConformalDecals 的拉丁字体（Carlito / Gyrotrope / LeagueSpartan / NimbusSans / Neuropol），
KSP 本体中文字体在 `KSP_x64_Data` 的 bundle 里，取不出来。

**优先级：M0 第一优先级（01 §8 修订 8）。** 这一层不通过，后面全是白干，所以它排在 M0 验收的第一条，
而不是「收尾阶段再补字体」。

> **v0.7 更正（D36）**：D33 里「**随包** OFL Noto Sans SC 子集」且**作为默认档**这半句**已被 D36 取代** —— 默认档改为 `OsFont`（系统字体），
> 随包字体降为可选档、排在 **M4**。历史留在这里：D33 的结论「字体是硬前提、不能赌环境」仍然成立，
> 被推翻的只是「默认用随包字体」这个实现选择，三条理由见下面做法 1 与 §12.1。

**三档模式（v0.3 定稿，配置项 `FontMode`）**：

| 值 | 行为 | 什么时候用 |
|---|---|---|
| `Off` | 完全不碰字体 | 玩家自己装了中文字体包，或只想读翻译文本 |
| `OsFont`（**默认**，D36） | `Font.CreateDynamicFontFromOSFont(name, size)` 用系统字体建动态字体资源 | 默认档：Windows 开箱可用；本机真游戏实测 `os font="Microsoft YaHei"`、legacy `Font` 16/16 含 CJK |
| `Bundled`（可选档，排在 **M4**） | 加载随包字体（D33 原案：OFL 授权的 **Noto Sans SC 子集**，5–8 MB） | 没有系统中文环境的玩家（Linux/Proton、精简 Windows）**显式选择**；需要一份我们还没做的字体资产 |

降级链：默认 `OsFont` 找不到含 CJK 的系统字体 → 进「降级模式」（文本照翻、字形显方框，见做法 7）；
`Bundled` 档找不到随包文件 → 自动退 `OsFont` → 仍建不出来 → 同样进降级模式。

**TMP 侧的第二个开关（v0.7 补，配置项 `TmpMode`）**：`Auto`（默认）/ `KeepSource` / `Force`。
`Auto` 的真实语义是：**拿不到 CJK 字形就保留原文，不显示方框** —— 本机真游戏实测 TMP 24 个 font asset 含 CJK 的 **0** 个，
所以 TMP 侧默认走「原文可见」而不是「方框一片」；`KeepSource` 完全不碰 TMP 字体；`Force` 才强行注入 CJK fallback（实验档）。

**做法**：
1. **默认档（`OsFont`）走系统字体探测**：`Font.GetOSInstalledFontNames()` + `Font.HasCharacter()` 精确匹配含汉字的系统字体；
   本机真游戏实测可拿到 `Microsoft YaHei`，legacy `Font` 16/16 含 CJK —— uGUI 注入线是通的。
   **`Bundled` 档（可选，M4）才随包自带**一份 OFL 授权的 CJK 字体（Noto Sans SC 子集，5–8 MB，D33 原案）。
   **为什么默认不是 Bundled（D36 三条理由，别重开）**：
   ① Bundled 需要一份**我们还没做的资产**（子集化 + 许可审查 + zip 从 996 KB 涨到 6–9 MB），是独立工作量，不是一行默认值；
   ② OsFont 在本机已被真游戏实测证明可用，而 TMP 侧 24 个 font asset 含 CJK 的 0 个（走 `TmpMode = Auto` 保留原文）；
   ③ 默认值必须是「装上去就能用」的那一档 —— OsFont 在 Windows 开箱可用，Bundled 留给没有系统中文环境的玩家**显式选择**。
   **实现约束**：Unity 运行时没有「把 TTF 字节直接 new 成 `Font`」的公开 API —— `Bundled` 档必须走**随包 AssetBundle**
   （里面是编好的 `Font` 与 `TMP_FontAsset`），不能指望 `File.ReadAllBytes` + 构造器；
2. 运行时构造/取得动态 TMP 字体资源：`TMP_FontAsset.CreateFontAsset(font)` 并置
   `atlasPopulationMode = AtlasPopulationMode.Dynamic`（字形按需入图集，子集不用预先烘焙全字）；
3. 逐字体兜底：postfix `TMP_Text.set_font` / `LoadFontAsset`，把 CJK asset **追加**进该 font 的
   `fallbackFontAssetTable`（mod 自带花体保留拉丁字形，缺字自动落到 CJK）。
   **不改 `TMP_Text.font`** —— 换掉主字体等于抹掉 mod 自己的风格（字重、描边、花体全丢），这是 D33 之外的实现红线；
4. 全局兜底（可选）：把该 asset 塞进 `TMP_Settings.defaultFontAsset.fallbackFontAssetTable`，只对没被第 3 条覆盖的文本生效；
5. uGUI `Text`：用 `Font.HasCharacter()` 判定缺字 → 换成我们的 CJK Font，保留 size/lineSpacing/alignment/fontStyle；
6. **懒加载**：只有当「这条文本是我们翻译过的那条」（译者命中）时才动字体 —— 命中后调一次
   `FontFallback.Ensure(text, tmpText)`，按 fontAsset 记「已注入」缓存，**绝不给全游戏每个 TMP_Text 拉 fallback 表**；
7. **降级行为（必须明确，不许静默）**：三档都建不出字体时**文本照翻**、字形显方框，并打一条可诊断的日志：
   `[UI18n] font fallback unavailable (mode=<OsFont|Bundled>, reason=…): Chinese text will render as □; translation still applied`，
   同时把 `fontFallback=unavailable` 计数进覆盖率指标（§5.5）；

## 4. 字典数据模型

### 4.1 三层键（精度 vs 覆盖的折中）

| 层 | 键 | 精度 | 覆盖 | 用途 |
|---|---|---|---|---|
| ctx | {asm}\|{typeFullName}\|{member}\|{ordinal} + textHash | 最高 | 最差（mod 升级漂移） | 有歧义的串 |
| site | {asm}\|{textHash} | 中 | 中 | 默认 |
| global | {textHash} | 低 | 最高（跨 mod 复用） | 通用按钮词 |

查找顺序 ctx → site → global，命中即返回，并记 hitLevel 供统计。
反向：同一 global hash 在不同 ctx 需要不同译文时，允许 ctx 覆盖并进「歧义清单」送人工复核。

**global 层的准入规则（01 §8 修订 4，C5）**：global 只收**人工审核过**的通用词（Yes / No / Save / Cancel 这类），
**不自动扩充** —— 不因为「多个 mod 里都出现同一个串」就自动升格为 global。理由是 01 §6.1：44 条 ≤6 字符的
通用键在无门控的全局 hook 下直接造成跨 mod 污染（把别人界面里的 "Max" 也变成中文）。

**per-mod 冲突仲裁（C5 的后半句）**：同一个 hash 在 A mod 要译、在 B mod 要保留原文时，
用 `packs/<lang>/<modId>.overrides.json`（人工锁定，LLM 不得覆盖）在该 mod 的加载视图里覆盖 global 结果；
无 override 时按 ctx → site → global。仲裁过程必须落日志（`[UI18n] global conflict: {hash} {modA}/{modB}`）
并进歧义清单送人工复核，**不许静默择一**。

**查找算法只有一条路径：整串精确键（归一化 → 哈希 → 查表）。禁止子串替换，禁止「包含即替换」（01 §8 修订 5，C6）。**
01 §4.3 的事故是对任意文本做 `text.Replace(k, v)`：谁往表里放一个 "OK"，`"BREAK"` 就变成 `"BR确定EN"`。
前缀/模板类规则（例如 `12) Something` 的数字前缀）只在**整串匹配失败**时启用，且必须「命中后继续扫描更精确的规则」，
不允许命中即 `return true` 提前截断（RP1GUIZh 的 `Prefixes` 就是这么把后续规则全废掉的）。

**为什么不用纯文本做 key**：RP1GUIZh 就是纯英文文本当 key（DLL 里 347 条 UTF-16 串，
"Add to Plans"、"Astronaut base cost" 直接当键），能跑，但一个 mod 一个硬编码字典、无法复用、
同词不同义无法区分。三层键是它的可扩展版本。

### 4.2 归一化（Normalizer）

- 保留：<<1>> <<2>>、{0}、%s、\n、<color=…> <b> <i> <size=…> <sprite …>
- 折叠：首尾空白、连续空格、\r\n → \n、弯引号 → 直引号、零宽字符删除
- 富文本标签参与哈希时**规范化属性顺序与大小写**（<Color=Red> ≡ <color=red>）
- 数字/单位不归一化（<<1>> 已由 KSP 处理）

### 4.3 文件格式

> **v0.2 备注（与实现契约对齐）**：运行时与流水线的**实际**源格式是 **JSONL**（一行一条，固定字段
> `h / n / s / t / mod / ctx(可选)`，与 `UI18n.Core.Dict` 的解析契约、`tools/i18n_tools` 的输出一致，见
> [06-工程骨架与构建.md](06-工程骨架与构建.md) §5）。下面这段结构化 JSON 是它的**展开视图**，供人 review 阅读，
> 不作为落盘格式。

**源（人可读、可 review、进 git）** `packs/<lang>/<modId>.jsonl`（结构化视图如下）：

```
{
  "schema": 1,
  "modId": "AJE",
  "modVersions": [">=1.16.0"],
  "srcLang": "en-us",
  "lang": "zh-cn",
  "entries": [
    {
      "k": "site:AJE:8f3a…",
      "c": "AJE.AJEAtmTools:UpdateInfo",
      "s": "Intake Area",
      "t": "进气面积",
      "st": "auto",
      "h": "3f9c1d…"
    }
  ]
}
```

- k 三层键，c 上下文（可选），s 源文（用于 diff / 复核 / 过期检测），t 译文，
  st 状态（auto | machine | review | keep），h 源文哈希。

**运行时格式（v0.2 定稿，D35）**：`Packs/<lang>/<modId>.jsonl` —— 一行一条，字段
`h/n/s/t/mod/ctx`（`h` 是 16 位小写 hex 字符串），这是**唯一权威的运行时格式**；
加载时流式逐行解析，只留命中需要的 `h → t` 两列，不进中间对象树。解析契约与字段含义见
[06 §5](06-工程骨架与构建.md)。

**二进制包 `.uip`：deferred（不做，M3 之后再说）**。v0.1 草案曾计划 `Packs/<lang>/<modId>.uip`
（`Dictionary<ulong,int>` 索引 + 字符串池，首次加载后缓存到插件数据目录，按 mtime + size 校验）。
降级理由：8,975 条量级下 JSONL 的解析成本可忽略，而二进制格式要在 JSONL 之外多养一条
序列化 / 校验 / 调试链路；用可 grep、可 diff、能手改的文本格式换掉一个编译产物是更划算的交换。
真要撞上加载耗时问题，再按 D35 重新评估。**在此之前，文档、CI、脚本都不得把 `.uip` 当作现行格式来生成或读取。**

### 4.4 过期与降级

h（源文哈希）与实际字符串哈希不符 → 该条视为过期，回落英文并计入 staleCount；
整个 pack 的 modVersions 与实际版本不符 → 降级使用 + 提示更新。

覆盖率指标（hit / miss / stale）是**发版硬要求**，不是可选报表 —— 定义、采集点与门槛见 §5.5。

## 5. 采集器

### 5.1 静态 · IL 调用点分析（核心算法）

**硬规则（01 §8 补充修订，C8）：字典只能从 IL 取真实字面量，禁止照源码手抄。**
RP1GUIZh 的 25 条 `"BP Cost: {buildPoints:N0}"` 就是手抄 C# 插值模板的代价 —— 运行时 IL 里只有
`ldstr "BP Cost: "` + 一次格式化调用，这 25 条**永远命中不了**（01 §4.1）。所以采集产物必须带
`method / ordinal / ilOffset`，任何一条都能回查到 IL 位置。

用 Mono.Cecil 遍历每个 mod 程序集：

1. 逐方法扫描 IL，维护一个「字面量栈」；
2. 遇到 `ldstr` 记录字面量；遇到 `call/callvirt` 时回溯最近的字面量，
   判定目标方法是否属于**已知 UI sink 集合**（Text.set_text、GUILayout.Do*、GUI.*、
   ScreenMessages.PostScreenMessage、Localizer.Format…）；
3. 命中 → 产出 {asm, type, method, ordinal, literal}，即 ctx 键；
4. 同时处理 string.Concat 模式：`ldstr "Fuel: "` + ldloc → 记录**片段**并标记 isFragment，
   留给动态探针补全；
5. 过滤：含 [ModName] 前缀的日志串、含 Exception / failed / .dll / .cfg / http 的串、
   长度 > 300 或 < 3 的串、纯格式符、纯路径。

输出 `packs/pool.jsonl`（v0.1 草案里叫 `data/src/<modId>/strings.json`，见 §6.1 的对应表），并附覆盖率统计。

> **实现实况（v0.9）**：上面这条 IL 路径**1.0.0 里还没落地** —— `tools/i18n_tools/harvest.py` 目前只收 `.cfg`（`:133-134`，全文件无 `Managed`/`.dll`），
> 所以 `packs/pool.jsonl` 的 12,792 行只有 `src=loc` 2,948 + `src=cfg` 9,844，**IL 字面量 0 条**。
> 这条路径排进 v1.1：独立产物 `packs/il-strings.jsonl`（不动已冻结的 pool），首批 271 条 distinct，方案与量级见 [04 §3.6](04-翻译流水线与预处理.md)。
> 本节其余内容仍是**设计**，不是已实现行为。

### 5.2 静态 · cfg 文本

正则扫 title | description | displayName | guiName | manufacturer，排除以 # 开头的（已是 tag）。
本机实测 6,745 条唯一值。

### 5.3 静态 · 原生 Localization 目录

解析 `Localization/*.cfg` → key → {lang → text}，**按 mod 目录做语言并集后再求差** → 待翻译 key（3,331 条，见 §1 更正说明）。
这条路径**完全不需要跑游戏**，可以独立成第一个可交付物。

### 5.4 动态 · 运行时探针

- `HarvestMode=true` 时，每个 patch 记录 (asm, text, caller, hitLevel) 到
  `PluginData/UI18n/harvest.log`（JSONL，按 asm 分文件，去重；插件数据目录见 D34 与 [06 §6.4](06-工程骨架与构建.md)）；
- 玩家游戏内热键「上报缺失文本」→ 抓取当前屏幕未命中的串 + 上下文 + 截图 → 打包 zip；
- 拼接串在这里自然补全：把数字/单位抽象成 <<n>> 后与静态片段合并。

### 5.5 覆盖率指标（hit / miss / stale）—— 发版硬门禁

每次发版必须产出并归档下面三项计数，缺一项不许发（01 §8 补充修订，C8）。
理由是 RP1GUIZh 的原病：它「以为翻了 399 条」，实际命中多少、落后英文多少，**没人知道** —— 它连 stale 概念都没有，
上游英文一改，译文静默失效。

| 指标 | 定义 | 采集点 | 门槛 |
|---|---|---|---|
| hit | 查表命中并成功改写的次数，按 hitLevel 分 ctx / site / global | 运行时计数器，按 asm 聚合 | 目标 mod 命中率 ≥ 90% |
| miss | 归一化后三层都没有条目的次数（keep 即译文 == 源文，单列计数） | 同上 | 单 mod 未命中 Top 20 进下一轮采集 |
| stale | 源文哈希与 pack 里 `h` 不符、回落英文的次数 | 加载期校验 + 命中期比对 | > 0 即触发该 mod 重采 |

计数器是**零分配**的（`long` 字段自增），只有热键导出或退出时汇总一次，导出格式见 02 §8 的数据契约。
指标按 `<asm>/<hitLevel>` 两级聚合，随发版写进 `packs/index.json` 的 `coverage` 字段，供 CKAN 页与 PR 说明引用。

### 6.2 GitHub Actions

| 工作流 | 触发 | 动作 |
|---|---|---|
| harvest.yml | 手动 / 每周 | 采集 → 与上次 diff → 只产出 delta |
| translate.yml | harvest 产物 | 分批（30–60 条/请求）调 LLM，带 ctx + glossary + 同 mod 已批准译文做 few-shot |
| validate.yml | PR | 硬门禁（见 6.3）→ 通过标 auto，失败标 review |
| publish.yml | main 合并 | 校验 JSONL → sha256 → 更新 index.json → 推 gh-pages |

**成本控制**：按 sha1(ctx + src + glossaryVersion) 缓存，跨 mod 复用命中率极高；
首次全量约 4 万条 × 约 60 token ≈ 250 万 token，增量通常 < 1%。
便宜模型初翻 + 强模型只复核被标 review 的条目。

### 6.3 校验硬门禁（占位符错位是唯一会直接崩 UI 的错误）

1. 占位符多重集完全一致：<<n>>、{n}、%s / %d；
2. 富文本标签配对与白名单（color / b / i / size / sprite / align / line-height），数值上限；
3. 长度比 len(zh)/len(en) ∈ [0.15, 1.8]，越界进 review；
4. 术语表命中率（专有名词必须按 glossary 译或保留原文）；
5. 译文 == 源文 → 标 keep（Kerbin、MechJeb、RD-107 之类白名单）；
6. 译文含非法字符（\0、\r、超长 > 2000）→ 直接拒绝；
7. 空译文 → 拒绝。

### 6.4 真正的闭环

自动翻译的译文**应该 PR 回原 mod**（多数作者乐于收 zh-cn.cfg）。
这既提升覆盖率，也让本项目从「外挂汉化」变成「上游贡献」，长期可缩小 L2 的负担。

## 7. 分发

### 7.1 主干：CKAN

KSP 玩家的标准分发方式是 CKAN，**不要自研更新器做主干**：
- 一个 `UniversalI18n` 核心模块 + 每语言一个数据包模块（`UniversalI18n-ZH`）；
- CKAN 自带版本管理、依赖、离线缓存、SHA 校验、回滚；
- 缺点：需要玩家装 CKAN（但 RP-1 玩家 100% 有）。

### 7.2 增强：游戏内在线增量（可选）

- UnityWebRequest 拉 `index.json`（If-None-Match），按 modId@version 选包；
- SHA-256 校验 → 写 `GameData/UI18n/Packs/`；
- 失败静默降级到随包 baseline；
- 域名白名单：github.com / raw.githubusercontent.com / *.github.io；
- 默认 CheckForUpdates=true、AutoDownload=false（联网行为需玩家知情）；
- 上报（D31）：按钮存在但**默认关闭**，开启时先弹出「将要上传的条目清单」预览 + 隐私声明，只上传文本与归因哈希，不传路径、不传存档、不传 KSP.log；内容可逐条取消勾选。

**Packs 布局：从「装进去」到「读得到」的唯一路径（v0.3 判据化）**

这两条是**真实部署才暴露的致命缺陷**，不是理论风险。写成判据，任何人部署完都要能自证：

- **判据 1（目录层级）**：运行时**只读** `GameData/UI18n/Packs/<lang>/*.jsonl` —— `ConfigLoader.cs:156` 是
  `Directory.GetFiles(dir, "*.jsonl", SearchOption.TopDirectoryOnly)`，语言目录名按 `Localizer.CurrentLanguage`
  小写 + 下划线转连字符后先精确（`zh-cn`）再主语言（`zh`）。
  **平铺丢在 `Packs/` 根下的 `*.jsonl` 一条都读不到**：早期实现读的是平铺目录，结果按契约路径放的包
  （`Packs/zh-cn/*.jsonl`）**一条也没读到 —— 字典恒空，patch 全装上了却一个都不命中**。
  自证方法：KSP.log 里必须出现 `[UI18n] pack loaded: zh-cn/<modId>.jsonl, entries=+N`（N > 0）与
  `[UI18n] dictionary: entries=N, parseErrors=0`；目录里明明有 `*.jsonl` 却打出
  `no pack dir for language=…, dictionary is empty` 或 `no *.jsonl in …`，就是布局错了。
- **判据 2（源产物污染）**：`Packs/` 根下的 `pool.jsonl` / `glossary.jsonl` / `inventory.json` 是**流水线源产物，
  永远不是字典**。本机实测（把这些文件逐行灌进 `DictPack.LoadJsonLines`）：`pool.jsonl` 12,792 行 →
  **entries=0 / parseErrors=12,792**；`glossary.jsonl` 2,126 行 → **entries=0 / parseErrors=2,126**；
  而 `smoke/_smoke.jsonl` 34 行 → entries=34 / parseErrors=0。原因在解析器契约：`Dict/JsonLineReader.cs:90`
  要求 `h`、`:102` 要求非空 `t`，源产物里没有 `t`。
  自证方法：出现 `dictionary: entries=0, parseErrors=<等于文件行数>` 就是「把源产物当字典装了」，不是「翻译没生效」。

这两条已同步进 [06 §6.5](06-工程骨架与构建.md)（部署判据与排障）。

### 7.3 信任模型（别人的文本会进你的 UI）

- pack 只接受**纯文本 + 白名单标签**，加载前消毒；
- 拒绝 <size=9999>、引用不存在图集的 <sprite>、超长串；
- 签名：Ed25519 对 index.json 签名，公钥硬编码；或退化为「只信任 HTTPS + 固定仓库」；
- 供应链：CI 只用固定版本 Action，packs/ 走人工 review 合并。

### 8.2 八条约束的可执行表述（违反即返工）

**C1 · 只改传入值副本。** uGUI/TMP 用 `static void Prefix(ref string value)`，只赋 `value`；
IMGUI 用 `static void Prefix(ref GUIContent content)`，且必须 `content = new GUIContent(translated, original.tooltip)`。
`GUIContent.Temp()` 返回共享缓存实例，原地写 `content.text` 会让全游戏共用的对象**永久**变中文，切回英文也不恢复（01 §6.2）。
违规判据：反编译插件 DLL，出现对 `GUIContent::set_text` 的调用即返工。

**C2 · hook 层不准碰游戏。** 插件里 `Transpiler` 方法数必须为 0；Prefix/Postfix 里不得出现任何游戏 API 调用
（`Localizer.*`、`PartLoader`、`InputLockManager`、反射玩法类型……），也不得用 try/catch 去「包住」游戏方法体。
try/catch **只能**出现在装 patch 的注册循环里：逐 patch 捕获 → 记录「目标 + 原因」→ 计数，最后打印 `installed ok/total`。

**C3 · patch 目标白名单（渲染层可证明）。** 允许清单：`UnityEngine.UI.Text.set_text`、
`TMPro.TMP_Text.set_text`（声明方法，不是 `TextMeshProUGUI`）、`UnityEngine.GUILayout.DoLabel / DoButton / DoRepeatButton / DoToggle / DoWindow`、
`UnityEngine.GUI.Label / Box / Button / Toggle（4 参与 5 参两个重载）/ Window` 的 `GUIContent` 重载、
`UnityEngine.TextMesh.set_text`、`ScreenMessages.PostScreenMessage(string, …)`。
拒绝清单：任何 `Assembly-CSharp!KSP.*` 与 mod 命名空间下的**领域类型**（`RP0.*` / `KCT_GUI` / `Contracts.*` / `PartLoader` …）。
CI 校验：`src/UI18n.Runtime` 在构建期生成 patch 清单（目标签名的显式表），与上述白名单比对，出现白名单外条目直接 fail；
PR 不允许以「只是读一下」「只是为了定位」为由加白 —— 01 §1 的四类事故每一条都始于「顺手改一下」。

**C4 · 语言门控一次性。** 见 §8.4。

**C5 · global 层人工审核 + per-mod 冲突仲裁。** 见 §4.1「global 层的准入规则」与「per-mod 冲突仲裁」。

**C6 · 禁止子串替换。** 见 §4.1「查找算法只有一条路径」。前缀/模板规则不得 `return true` 提前截断。

**C7 · 字体兜底 M0 第一优先级。** 见 §3.4；M0 验收第一条就是「三处场景中文正确显示、无豆腐块」（§11）。

**C8 · 只从 IL 取字面量 + 覆盖率指标。** 见 §5.1 硬规则、§5.5 hit/miss/stale 门槛、§4.4 stale 处理。

### 8.3 per-mod 仲裁 policy（「优先支持 i18n 的 mod」）

每个 mod 算出一个 policy：

| 条件 | policy | 行为 |
|---|---|---|
| 有 `Localization/<当前语言>` 节点 | NATIVE | 完全不动，L2 跳过该 asm |
| 有 `Localization/` 但无当前语言 | NATIVE_PARTIAL | 只补该 mod 字典里没有的串（L0 优先，L2 兜底） |
| 引用 Localizer 但无 Localization 目录 | PARTIAL | L2 全量翻 |
| 都没有 | LEGACY | L2 全量翻 |

判定依据（两路）：
- 静态：Cecil 扫 Localization 目录 + Localizer 引用 + #autoLOC_ 字面量 → `capabilities.json`，
  key = assemblyHash(mtime + size)，可缓存到磁盘；
- 运行时：postfix `Localizer.Format/GetString` 记录实际调用者（仅 discovery 模式开 StackTrace）。

### 8.4 语言门控与语言切换（C4 的落地细节）

启动期在 `[KSPAddon(KSPAddon.Startup.Instantly, once: true)]` 的 `Start()` 里读一次 `Localizer.CurrentLanguage`：

| 条件 | 行为 |
|---|---|
| 语言以 `zh` 开头（OrdinalIgnoreCase）或 `ForceOverride = true` | 加载 pack → 装 patch → 打一行汇总 |
| 其它（en-us / de / ru …） | **一个 patch 都不装**，日志写 `[UI18n] language=en-us, patches skipped`，直接 return |

这是**一次性判断**，不是每帧判断：不装 patch 时 Harmony detour 根本不存在，运行时开销严格为 0（05 §6.2）。
也**不要**读 `settings.cfg` / `buildID.txt` 判语言 —— 本机实测两者与 `KSP.log` 首行互相矛盾，只有
`Localizer.CurrentLanguage` 的运行时值可信（见附录 A）。

运行期语言被切走（`Localizer.SetLanguage`）时**不卸载 patch**：Harmony 卸载不安全，且卸载后其他 mod 的 patch 顺序会漂移。
改为把全局 `bool HasAnyTranslation` 置 false 做单次短路（05 §6.2），切回中文再置 true。
轮询 `Localizer.CurrentLanguage`（每 30 帧一次）仍保留，但**只**用于这条短路开关，不用于装/卸 patch。

## 9. 性能预算

> 修订（见 05-原生性与性能调研.md §4）：以下数值已被实测替换。原拍脑袋值（命中 <50 ns / 未命中 <15 ns）在
> .NET Framework 4.7.2 + 0Harmony 2.2.1 上实测为 **命中 20.6 ns / 未命中 17.1 ns**，故按实测重写。

| 项 | 目标 | 实测 |
|---|---|---|
| 单次命中开销（哈希 + 查表 + 改写） | < 35 ns | **20.6 ns** |
| 未命中开销（哈希 + 查表 + 短路） | < 25 ns | **17.1 ns** |
| Harmony 调度开销 | 可忽略 | **+0.2 ns** |
| 分配 | 命中路径 0 分配 | 100 万次调用 **0 B** |
| 抓调用栈 | 仅首见串一次，全局预算 4,000 | **2,073 ns/次**（≈100 次查表） |
| 整帧增量 | < 0.1 ms（极端：3,000 次/帧） | 推算 **~60 µs（0.36% 帧）** |
| 启动增量 | < 200 ms（pack 解析，可缓存为二进制） | **72 ms**（round 1：42 文件 / 10,024 条，单包 max 21 ms，见 05 §3.4.3） |

实现要点：
- 先算哈希再决定要不要归一化（只有含 < 、连续空格、首尾空白的串才走慢路径）；
- 归一化用线程静态 char[] 缓冲 + Span<char>；
- 负缓存 + 「已翻译标记」避免同一串被翻两次（中文译文的哈希天然不在源字典里，第二层保险）。

| Q-F | 强制覆盖模式 | 提供开关，**默认关**；默认严格跟随 `Localizer.CurrentLanguage` | D32 |
| Q-G | 中文字体 | 随包自带 OFL 授权的 Noto Sans SC 子集（5–8 MB），不做系统字体探测 | D33（「随包 + 默认档」部分已被 **D36** 取代） |

两个「为什么」（避免后来者重新争）：

- **Q-E 选了「做按钮」而不是我推荐的「只做本地导出」**：C 类硬编码文本只能靠真实运行场景采到，而我们的探针跑不到玩家独有的界面组合（别人的 mod 组合 + 别人的语言设置）。但代价是必须先把「知情 + 预览 + 可关闭」做扎实，否则在 KSP 社区一次差评就足够毁掉项目——所以 B18（上报服务端设计）是它的前置。
- **Q-G 不做系统字体探测**：本机实测 `GameData` 下 **0 个 CJK 字体**，KSP 本体中文字体打在 `KSP_x64_Data` 的 bundle 里取不出来。Windows/macOS/Linux 的字体路径各异且可能缺字，赌环境的失败模式是「玩家看到一片方框」，而这恰好是本项目最不能出的错。

> **v0.7 补（D36）**：上面这条解释的是「为什么不把随包字体当作唯一手段」，但 D36 之后**默认档就是 `OsFont`** —— 会探测系统字体（`Font.GetOSInstalledFontNames()` + `HasCharacter()`），探测失败时**保留原文而不是显示方框**（`TmpMode = Auto`）。
> 所以两者不矛盾：不再赌「一定能找到系统字体」，而是「找到就用、找不到就不破坏可读性」；随包 `Bundled` 档留给显式选择的玩家，排在 M4。

### 12.1 v0.7 追加决策（D36–D39）

| # | 决策 | 理由 | 落地 |
