# 11 · M1 / M3 / M4 / M5 实施计划（v1，2026-10-29）

> 本文件梳理 M1、M3、M4、M5 四个里程碑的实施范围、补齐顺序与验收测试标准。
> 判定口径以离线可复跑的验证命令与确定性产物为准；游戏内实测单独列出。

## 1. 验收口径：怎么算「完成」

`docs/00` §11 的验收写的是玩家可见的结果（「游戏内 100% 命中，零报错」「CKAN 安装可用」「一周内进包」「≥5 个 mod 收到 PR」）。这些无法在本机判定，所以拆成两层：

| 层 | 判据 | 谁能判 | 证据形式 |
|---|---|---|---|
| **L-离线** | 生成物正确、门禁能红能绿、单测/自检全绿、幂等可复跑 | 本机 CI 与本机命令 | 命令退出码 + 报告文件 |
| **L-游戏内** | 真游戏里读到、显示对、零报错、帧率不掉 | 一台装了 KSP 的机器（用户跑一轮） | KSP.log 行 + 截图 |

**本计划只承诺 L-离线 全绿 + 把 L-游戏内 的跑法写成一条可照抄的命令**。任何声称「已验证」的结论都必须给出 L-离线 的命令输出，或指出这是 L-游戏内 待验。

## 3. 全局约束（动手前必须知道）

1. **包格式冻结**：`packs/<lang>/*.jsonl` 的字段只有 `h / n / s / t / mod / ctx`，`h` 是 `s` 归一化后的 FNV-1a 64；任何新信息走**新文件**，不许加字段。
2. **数据驱动**：代码里不许出现具体 mod 名（审计 `_audit/hardcode/` 已清账，别倒回去）。新特性一律「数据表 + 通用判据」。
3. **Runtime 本机编译不出**（无 KSP Managed / Harmony）。改 `src/UI18n.Runtime/**` 只能做 csc 语法校验 + 逐行复核，游戏内验证欠着——所以本计划把 Runtime 改动排在**离线可证的部分之后**。
4. **不引依赖**：python 只用标准库；.NET 只用 BCL（`UI18n.Core` 零三方依赖）。
5. **`dotnet test` 在本仓库被禁**（csproj 有 `error UI18N001`）：跑 `dotnet tests/UI18n.Core.Tests/bin/Debug/net10.0/UI18n.Core.Tests.dll`。
6. `_scratch/`、`_audit/`、`build/`、`dist/` 都在 `.gitignore`：**生成物不入库**，入库的是生成器 + 门禁。
7. `.ps1` 一律 UTF-8 **带 BOM**（write/edit 会剥，改完跑 `python _scratch/add_bom.py`）。
8. **不许回滚既有未提交改动**（工作区 45 个 M + 8 个 ??，是本轮与上轮的全部成果）。

## 4. M1 数据层

**目标**：把「英文→中文」的记忆落成 KSP 自己认的语言节点，让 `#LOC_*` 键在原生 `Localizer` 通道就返回中文（不经过我们的 Harmony 钩子）。
**验收（docs/00 §11）**：TriggerTech(550) + RO(1,138) + EER(164) + ROCapsules(160) = **2,012 key 全覆盖**，游戏内 100% 命中、零报错。

### M1-a 语言节点生成器 —— **本轮已落地**

- 产物：`build/native/<lang>/<Mod>.cfg`（生成物，不入库），内容是 `Localization { zh-cn { #LOC_x = 中文 } }`。
- **决策（偏离原设计，见 §10 风险 R1）**：生成**纯 KSP 语言节点 cfg，不用 ModuleManager 的 `@` 语法**。三条理由：① mod 生态里自带 `Localization/*.cfg` 的 mod 都不装 MM 也能生效，说明 KSP 会把多个 `Localization` 节点合并；② `UI18n.netkan.template` 现在只依赖 `Harmony2`（Fix-4），用 MM 语法等于反向把 MM 加回强制依赖；③ 纯 cfg 是静态数据，出错时可以整文件删掉回滚，`@` patch 出错会污染别人的节点。
- 数据来源：`packs/pool.jsonl` 里 `src=loc` 且带 `key` 的行（键 + 英文原文 + mod）⨝ `packs/zh-cn/*.jsonl`（英文 → 中文，按 `h(normalize(s))` 连接）。池的 loc 行本身就是「缺 zh 差集」，所以生成物天生只补缺、不覆盖官方译文。
- 门禁（任一不过就 `--check` 非 0）：key 形态 `^#[A-Za-z0-9_.\-]+$`、值非空、值不含换行/`{}`、值里「空白 + `//`」这种会被 cfg 解析器当注释吃掉的形态直接跳过并记账、占位符（`<<1>>`）多重集不变、同一 key 不重复、**生成后用 `cfgparse` 回读逐条比对**（往返相等才算没转义 bug）、总数 > 0。
- 统计（真实数据，2026-10-29）：池 loc 行 **2,948** 条 → 可解析到中文 **2,785**（94.5%）；四个验收 mod 合计 **1,826 / 2,012 = 90.8%**（RO 1,029/1,138、TriggerTech 496/550、EER 142/164、ROCapsules 159/160）。
- 测试：`python -m i18n_tools.mmgen --selftest`（并入 `selftest.py` 的 `test_extra_tools`），覆盖：连接逻辑、跳过规则、往返回读、幂等（跑两次字节相同）、空输入、坏 key、占位符不变、文件名清洗。

### M1-b 打包与安装接线（下一轮）

- `src/UI18n.Runtime/build-release.ps1`：把 `build/native/<lang>/**` 拷进 zip 的 `GameData/UI18n/Packs/<lang>/Native/`；`manifest.json` 增 `nativeFiles / nativeKeys`；`release-checks.ps1` 增三条断言（每个 cfg 括号平衡、跨文件无重复 key、每个文件 ≤ 256 KB）。
- `deploy.ps1`：staging 时同步该目录；`install-check.ps1` 逐文件 sha256。
- **不走更新通道**：`ZipSafety` 只装 3 段 `Packs/<lang>/*.jsonl`，`Native/<Mod>.cfg` 是 4 段，永远只随整包发布——这与 `display-names.json` 同一条规矩，要在 `docs/06` 写明。
- 测试：`release-checks.ps1` 对假包（缺 Native / 多 Native / 括号坏）能红；对真包能绿。

### M1-c 游戏内验证（需一台真机，用户跑一轮）

```powershell
pwsh src/UI18n.Runtime/deploy.ps1 -Install -Version <v>   # 装到 <KSP>\GameData\UI18n
```

判据：① KSP.log 里 `Localization` 相关零报错；② 四个零中文 mod（TriggerTech / RO / EER / ROCapsules）的界面文本**在不开 Harmony 翻译**（配置 `Enabled=false`）时也显示中文 → 证明走的是原生节点；③ 开回 Harmony 后同一处文本不重复翻译、不出 `<<>>` 残留。

### M1-d 覆盖率门禁（下一轮）

- `mmgen --stats --min-cover 0.85` 接进 `.github/workflows/i18n.yml` 的 `gates`；
  （初稿写的 0.95 不现实：实测桥接率 88.1%，缺口是 43 条非键形态 + 158 条池里没有中文，
  这些都不是「今天没翻译」，而是历史遗留；阈值 0.85 只守「连接坏了」这一种塌方。）
- 缺口清单落 `reports/mmgen-coverage.md`（按 mod 列「有 key 但没中文」的英文原文，直接就是下一批送翻的输入）。

### M1-e 幂等维护

- 生成物每次按「key 全集重算」，池里消掉的行自然从 cfg 消失 → 不加增量状态、不做 diff，天然幂等（测试里跑两次比字节）。

### M1-f 身份表字段推导（`mods.json` 的 folders / assemblies）—— **本轮已落地**

**问题**：`packs/mods.json` 是生产端身份表（modId / displayName / ckan / assemblies / folders / aliases），
82 条记录的 `assemblies` / `folders` / `aliases` **全是空数组**。不是没填，而是这三个字段只能从
**装机后的磁盘**读出来（哪个文件夹属于哪个 mod、里面有哪几个 DLL），仓库里没有这份事实——
而 `audit` / `mod resolve` / `submission` 都要靠它回答「这句话是哪个 mod 的」。

**做法**：`tools/i18n_tools/modmap.py`，只做「磁盘事实 → 身份表」这一步。

- 扫 `GameData` 的**一级子目录**（KSP 的 mod 边界，CKAN 与 `PackLocator` 同口径），向下最多 3 层收 `*.dll`。
- 映射规则**复用** `policy.folder_mod_id`（精确 → 去 `000_` 前缀 → 大小写不敏感）：绝不引第二套别名表。
- **不猜**：磁盘上没匹配上任何 modId 的文件夹进 `unmatched` 报告，由人决定是不是新 mod。
- **不越权**：写盘一律转成 `api mod put` 命令走 `api.main`（packs 唯一写入口，带 journal 与门禁），
  本工具自己一个字节都不碰 `packs/mods.json`。
- **可空跑**：没有 GameData 的机器上 `--stats` / `--check` 打 skip 并 exit 0（仓库本来就不该带装机路径），
  有缺口 `--check` exit 4。

跑法：`python -m i18n_tools.modmap --gamedata <…>/GameData --report reports/mod-mapping.md`，
确认后 `--apply`。自检 36 项（合成 GameData，含 dry-run 不动盘、apply 幂等、坏 schema 拒绝）。

## 5. M3 CI 流水线（只剩 CKAN 分发）

**目标**：`dist/` 里出一个 CKAN 客户端能装的 `.netkan`，且它被门禁校验过。
**验收（docs/00 §11）**：CKAN 安装可用。

### M3-a netkan 字段校验器（`tools/check-netkan.py`）

必填与一致性：`spec_version`、`identifier`、`name`、`abstract`、`author`、`license`、`version`（**必须等于 zip 内 `UI18n.version` 与 `manifest.json`**）、`ksp_version`（1.12.x 范围）、`download`（URL 形状 + 指向本次 zip 的 sha1/sha256 字段）、`install` 段（`GameData/UI18n` → `GameData/UI18n`，与 zip 内目录逐条对齐）、`depends`（只有 `Harmony2`）。
测试：坏字段矩阵（缺字段 / 版本不等 / install 段错 / depends 混进 ModuleManager / zip 与 netkan 条目数不一致）每一条都要能红。

### M3-b CKAN repo 骨架 + 发布脚本

- `tools/publish-ckan.ps1`：断言 netkan 通过 `check-netkan`，产出 `dist/ckan/UI18n-<version>.netkan` + 一段可直接贴进 CKAN-meta PR 的说明（本仓库不发 GitHub Release，发行版已被维护者要求删除）。
- 文档：`docs/06` 补一节「CKAN 分发流程」（谁持有 CKAN-meta 的 PR 权限、版本号策略、`ksp_version` 跟随）。

### M3-c CI 发布 job

`.github/workflows/i18n.yml` 增 `release` job（`workflow_dispatch`，`release=true` 才跑）：build-release → release-checks → check-netkan → 上传 artifacts。**不创建 GitHub Release**。

### M3-d 可达性验证（需真机/需网络）

`download` 指向的 URL 必须真能下到同一个 zip；离线只校验形状与哈希字段，真实安装由一次 CKAN 客户端安装验证。

## 6. M4 动态上报链路（B18 定案）

**目标**：玩家在游戏里按一个默认关闭的按钮 → 我们收到他独有的缺失文本 → 一周内进包。
**验收（docs/00 §11）**：玩家上报 → PR → 一周内进包。

### M4-a 传输层定案：**用 GitHub Issue，不建服务端**（`docs/12-上报闭环设计.md`）

理由：`accept-submission-issue.ps1` + `journal_gate` + `submission.py` 已经在跑（M3 链路验收过一次），Issue 天生带身份、时间戳、可见性、审阅、限流、隐私声明；自建服务端要额外承担合规、可用性、滥用与成本，而收益只是「自动化程度」。**这同时把 B18 从「P0 阻塞」降级为「写清楚契约」。**

契约（bundle schema 已有）：字段、去重键（`h` + `sha256`）、单包大小上限、隐私清单（**不收**：路径、机器名、存档、用户名；**收**：缺失英文原文 + 出现次数 + mod 包名 + 语言码 + 游戏/KSP 版本）、失败退路（导出文件手动贴）。

### M4-b 客户端（Runtime，本机只做静态校验）

- `UI/PrefsPanel` 增「上报」区：默认关；开启时必须先看「将要上传的内容」预览（前 N 条 + 总数 + 隐私声明）；三态（关 / 开但不自动 / 开且定时）。
- `Submission/` 已有 bundle 与 exporter：补字节统计与「预览文本」生成（放 Core，可单测）。
- 测试：Core 侧 `SubmissionBundle` / `SubmissionExporter` 单测（本机可跑）——预览文本与 bundle 内容一致、超限拒绝、隐私字段不在 payload 里。

**已落地（v1.7）**：
- Core：`src/UI18n.Core/Submission/SubmissionReport.cs`（361 行，纯 BCL 无 Unity 依赖）——`Compose()` 深拷贝 bundle → `SortDeterministic()` → 超 `LimitEntries`(400) 截断 → **重算 `ComputeId()`**（不重算会被 accept 以 `submission-id-mismatch` 拒收）→ 生成 Title / Body / 预填 URL；URL 超 `LimitUrlChars`(7000) 时 `BodyInUrl=false` 并重建不带正文的 URL；文案全在 `SubmissionReportText`（默认英文，**Core 里没有中文**），Runtime 用 `T()` 灌。
- Runtime：`src/UI18n.Runtime/Submission/SubmissionIssue.cs`——`Build(bundle)` + `Open(report)`（只 `Application.OpenURL`，零网络栈），`SubmissionExportResult.Bundle` 透出已构建的 bundle，面板投稿区新增「上报到 GitHub」按钮（未导出时 `GUI.enabled=false`）。
- 测试：`tests/UI18n.Core.Tests/SubmissionReportTests.cs` 16 例（截断重算 id / 不改入参 / 排序稳定 / payload 仍过 `TryValidate` / URL 转义 / 长正文降级 / 占位符写错不抛）→ Core 975 例全绿。

### M4-c 接收侧

- 新增 `tools/accept-submission-bundle.py`：本地文件路径 + Issue 正文两条输入走同一条 candidates / journal 流程（现在只有 Issue 那条）。
- 测试：`--selftest` 覆盖重复投递幂等、无 consent 拒收、手改被 `journal_gate` 判 `sha-mismatch`（已有反向测试，扩到文件路径输入）。

**已落地（v1.7，对应 docs/12 §12.6 的四项校验）**：
- `submission.py`：`h` 重算不一致 → `gate/submission-hash-mismatch`（原来是 warning，按 docs/12 §12.3「必须等于」改成拒收）；新增 `known_mods` 形参，mod 查不到 → `gate/submission-mod-unknown`。
- `api.py`：新增 `known_mod_ids(ctx)`（= `packs/mods.json` ∪ 现有包文件名，**只来自数据文件**）；`cmd_submit_accept` 把它传给 `SUB.plan`。
- 重复投递 / 与包去重沿用 `existing_state`（同内容 `already:true` / 同 id 异内容 `submission-id-conflict`）与 `pack_hashes → covered`。
- 测试：`submission --selftest` 48 项、`api --selftest` 173 项（新增 h 重算、未知 mod、白名单放行三条负例/正例）。

### M4-d 在线增量

- `tools/publish-update.ps1` 已有雏形：补版本比较（manifest `version` 单调）、断点续传不做、**失败必须回滚**（装坏包不能留在 GameData）。
- 测试：Core `UpdateManifest` 单测 + 假 zip 安装矩阵（缺文件 / sha 不符 / 版本回退 / 半途中断）。

**已落地（v1.7）**：
- 客户端「要么全装、要么一个字节都不动」：新增 `src/UI18n.Core/Update/PackInstallTransaction.cs`（`InstallPlanFile` / `InstallTransactionResult` / `PackInstallTransaction`），三段式——先全验文件名 → 内容落 `<target>.ui18n-new`（与磁盘逐字节相同的记 `Unchanged` 跳过）→ 逐条 `File.Replace`（旧文件留 `.ui18n-bak`）→ 回读尺寸校验通过才删备份；任何一步失败按**逆序回滚**（有备份的还原、新装的删掉），回滚不全会把原因改写成 `rollback-incomplete (N file(s) could not be restored; …)`。另有 `CleanStale` 收尸：进程被杀后下次启动把 `.ui18n-bak` 还原 / `.ui18n-new` 删掉。后缀刻意不以 `.jsonl` 结尾，`PackLocator` 的 `*.jsonl` 扫描不会把半成品当包读。
- `UpdateWorkflow.InstallFiles` 改走事务（先 `CleanStale` 再整批 `Commit`），失败时日志变成 `update: install failed (<reason>) -> N file(s) were restored, packs are exactly as before`。

### M5-e 字库字符集（字体兜底的验收侧）—— **本轮已落地**

M5-b 做完了「字库可信」（sha256 / 许可 / 预算），但没人回答过另一半问题：**这份字库够不够用**。
子集字库最典型的翻车不是文件坏，而是少几个字 —— 文件校验全绿，玩家屏幕上一排方框。而这一侧
原本连依据都没有：仓库里没有任何地方记录「译文一共用到哪些字」。

- **新工具** `tools/i18n_tools/fontcov.py`（纯标准库，自检 48 项）：
  - `--write` / `--check`：把**会上屏**的字符抽成确定性产物 `packs/charset-zh-cn.txt`（按码位升序、一行一个字符）。
    来源只有四处：`packs/zh-cn/*.jsonl` 的 `t`、`packs/overrides.jsonl` 的 `zh`、`packs/glossary.jsonl` 的 `zh`、
    `packs/zh-cn/display-names.json` 的 `names`。`conventions.jsonl`（只进提示词）与 `n`/`s`（英文原文）不收。
    空白与控制字符不写进文件（只计数），否则 diff 全是噪音。
  - `--probe <字体>`：自己读 sfnt（TTF / OTF / TTC、cmap format 0/4/6/12，含 `idRangeOffset` 分支与 `gid=0` 不算覆盖），
    报这份字体相对产物缺哪些字；子表优先级 (3,10) > (3,1) > Unicode 平台 > (3,0)。
  - `--find <字符|U+XXXX>`：缺字时定位是哪条译文（`overrides.jsonl` 与 `glossary.jsonl` 按 `zh` 查）。
  - 退出码：0 一致 / 4 产物过期或缺字 / **5 字体读不懂**（读不懂不是缺字，不能混成一个码）。
- **CI** `gates` 新增 `fontcov --check`：包变了、产物没跟上就红。真验一份字体要带字体文件，进不了 CI（本机可跑）。
- **实测**：产物 2,606 个字符（cjk 2,450 / ascii 93 / 全角符号 21 / 其它 42），来自 20,856 条文本。
  拿本机字库探：`msyh.ttc`（微软雅黑，2 个 face / 29,905 码位）缺 11 个、`Deng.ttf` 缺 12 个，
  **缺的全是符号/emoji**（`ℹ ▶ ▾ ⚠ ⚡ ✓ ✗`、变体选择符 U+FE0F、`🌐 📋 🗑`）——中文主体一个不缺。
  这直接给出两条结论：① 中文覆盖率不是问题；② 随包子集要么把这些符号打进去，要么把带 emoji 的译文改掉
  （`--find U+26A0` 指向 `packs/zh-cn/ksp_plugin_adapter.il.jsonl` 那条 `⚠️ [已失效 …]`）。
- **还剩**：字库资产本身（需要 Unity 打 AssetBundle）；产物与校验器已就位，资产一到就能验。
