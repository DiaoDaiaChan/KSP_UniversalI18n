### 4.3 崩溃定案：启动期被 Windows 强制终止（已排除插件嫌疑）

2026-10-23 01:54 有一次「自动化跑游戏」以退出码 `-805306369` 结束（无符号读作 `0xCFFFFFFF`），只跑了 15 秒就死，当时的第一怀疑对象是插件。**现在定案：不是插件，是 Windows 侧的 AppHang。** 证据链如下。

**① 现场（自动化脚本留下的记录，`build/logs/wait-and-run.log`，1,062 B）**

```text
01:52:03 等 pid 48768 退出
01:53:03 已退出
01:54:03 round start lang=zh-cn，改写 settings.cfg 的 LANGUAGE
01:54:03 启动 pid=32492
01:54:18 恢复 settings.cfg
Exception: …\_scratch\p1\run.ps1:54
  KSP exited on its own (exit -805306369) before main menu
round failed, exit 1
```

**② 系统侧（Windows 事件日志，01:54:18 同一秒两条）**

```text
id=1002  程序KSP_x64.exe版本2019.4.18.4260停止与 Windows 交互并已关闭
id=1001  故障存储段 ，类型 0
         事件名称: AppHangB1   响应: 不可用
         P1: KSP_x64.exe  P2: 2019.4.18.4260  P3: 5ffdc692  P4: bcfe  P5: 134217728
```

`id=1001` 的「事件名称: AppHangB1」就是定案依据 —— 进程是被「停止与 Windows 交互」判死的，不是托管异常退出。另在 01:41:28 还有一条 `id=1001`（AppHangTransient），说明这台机器在那段时间有 AppHang 环境问题。

**③ 为什么可以排除插件**

- 当时部署的二进制是 **26,112 B 的旧版**（现已停放为 `UI18n.Runtime.dll.old-9c712ab1`，sha256 `9C712AB13ED5E13E…`），而崩溃发生在「before main menu」，插件连托管代码都没进到。
- 同一代（01:56 起、同样不带新版插件）留存的日志 `build/logs/player-exp1-no-ui18n.log` 与 `build/logs/ksp-exp1-no-ui18n.log` 里 `[UI18n]` 出现 **0 次**，没有再出现 AppHang。
- 崩溃那一次的 `Player.log` 已被后续启动覆盖（KSP.log 里 01:5x 时段 0 行），所以只能靠事件日志 + 留存的同代日志下结论 —— 这也是为什么要把判据写死在下面。

**④ 反证：换成现行二进制后一切正常**

2026-10-23 07:51:46 启动、07:52:23 插件开始工作，16 条 `patch ok` 全绿、`installed 16/16 patches`、主菜单 `Total loading time to main menu : 113.190s`（完整日志见 05 §3.4.2）。现行 `UI18n.Runtime.dll` 是 42,496 B（sha256 `4F43A79199947A45…`）。

**⑤ 判据（以后遇到同样症状照这个查，别只看退出码）**

```powershell
Get-WinEvent -FilterHashtable @{LogName='Application'; Id=1002} -MaxEvents 20 |
  Format-Table TimeCreated, Message -AutoSize -Wrap
```

- 退出码 `-805306369`（= `0xCFFFFFFF`）单独看没有诊断价值：它只说明「进程没了」，看不出是谁杀的。
- 先看 `id=1002`/`id=1001` 有没有同刻记录；有 AppHangB1 就按环境问题处理，不要往插件上猜。
- 崩溃现场会被下一次启动覆盖 `Player.log`，所以**跑游戏前先把 `%USERPROFILE%\AppData\LocalLow\Squad\Kerbal Space Program\Player.log` 复制一份**，否则事后只剩事件日志。

**结论**：这一条从「致命风险」降为「已排除」，不再阻塞 M0；风险条目仍保留在 00 §10 第 16 条（附同一条判据），因为 AppHang 是环境级问题、可能再来一次。

## 13. v1.6：交互 API 与投稿回路（设计定稿 2026-10-26，m07240）

用户提出两件事：① 译文改动「标准版化」，不许 agent 直接改 JSON 文件；② 把「玩家实例采集 → 征得同意上传 → 自动翻译 → 按 mod 推送 → 玩家自选哪些 mod 用中文」这条回路确认下来。

**脱敏口径（Lead 裁决，docs/10 §6.3）**：私有值**只替换不丢串** —— 命中存档名 / 飞行器名 / Kerbal 名 / 玩家目录名 → 值换成 `<save>` / `<vessel>` / `<kerbal>`；**替换后整串再无可见字母**（只剩占位符 / 数字 / 标点）才整条丢。

落地时抓到两个真缺口（都在自己代码里，靠「读代码 + 两向断言」而不是靠跑绿）：
