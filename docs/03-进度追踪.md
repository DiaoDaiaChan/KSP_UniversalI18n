## 5. 决策日志

### 5.1 已定（有据可查，不再讨论）

| # | 决策 | 理由 | 出处 |
|---|---|---|---|
| D1 | MM 不能 hook，只能改 ConfigNode；Harmony 负责运行时拦截 | 两者是不同数据通道，混为一谈会导致架构错位 | 00 §2.1 |
| D2 | 采集靠 Cecil IL 调用点回溯 + 运行时探针，不用启发式筛串 | 启发式精度 5,423/157,268 ≈ 3.4%，不可用 | 00 §2.2 |
| D3 | 优先级倒过来：数据层 > Hook 层 | **3,331** 个缺中文的 key（旧记 16,331 是重复计数）用 MM 就能覆盖，成本远低于渲染层拦截 | 00 §2.3 |
| D4 | L1 不做 MM 字面替换，改运行时覆盖 + tags 中文别名 | MM 替换是加载期一次性、切语言失效、污染存档与排序 | 00 §3.2 |
| D5 | 字典三层键 ctx / site / global | 精度 vs 覆盖的折中 | 00 §4.1 |
| D6 | 分发主干用 CKAN，游戏内在线只做增强 | 复用现成生态，避免自研更新器 | 00 §7.1 |
| D7 | 与原生 i18n 仲裁用 policy = NATIVE / NATIVE_PARTIAL / PARTIAL / LEGACY | 用户要求"优先本来就支持 i18n 的 mod" | 00 §8 |
| D8 | 性能预算：**未命中 < 25ns、命中 < 35ns**、命中路径 0 分配、整帧增量 < 0.05ms（v0.3 按 05 §4 实测修订；旧的「命中 < 50 / 未命中 < 15」已作废） | 渲染层拦截必须几乎免费；实测未命中 17.1 ns、命中 20.6 ns | 05 §4、00 §9 |
| D9 | Prefix 只允许改传入值副本；禁止调用游戏 API；禁止 transpiler；禁止 try-catch 包裹游戏方法 | RP1GUIZh 的四类事故逐条反推 | 01 §8 |
| D10 | GUIContent 必须构造新对象，禁止原地写 | `GUIContent.Temp()` 返回共享缓存实例，原地写会污染全游戏 | 02 §4.3② |
| D11 | 键用 FNV-1a 64 位，不用 `string.GetHashCode()` | 后者跨进程/版本不稳定，无法做持久化键 | 02 §5.1 |
| D12 | 移除 RP1GUIZh | 它是伪装成汉化的玩法 hack，且不成熟，不能当参考实现 | m00184 |
| D13 | 探针只读、只碰渲染层、异常自吞、三道上限 | 避免重蹈 RP1GUIZh | 02 §2 |
| D14 | 探针 sink 按"第几个参数是 GUIContent"匹配，不按参数个数 | `GUI.Toggle` 有 4 参和 5 参两个重载 | 02 §4.3③ |
| D15 | 翻译用 `gemini-3.8-flash-high`，走 `http://100.111.24.121:8317/v1`（OpenAI 兼容） | 用户指定；实测 200 条/批 17.4 s 稳定、并发 4 可用 | 04 §1、m00421 |
| D16 | 批量翻译默认 `reasoning_effort: "none"` | 实测 completion tokens 1,387 → 553（省 60%），延迟减半，质量无差 | 04 §1.2 |
| D17 | 术语一致性靠「锁定 + 缓存 + 复核」三道工序，不靠 prompt | 实测同一词跨批必漂移（Apoapsis → 远地点/远拱点） | 04 §9 |
| D18 | 遮蔽只针对路径/URL/标识符/转义序列/代码；KSP 占位符与 TMP 标签不遮蔽、只校验 | 实测保留率 100%，遮蔽反而破坏中文语序 | 04 §5 |

| D20 | 缓存键 = FNV1a(text) + glossaryV + promptV + model | 术语表更新后只重译受影响条目，不做全量重跑 | 04 §11.3 |
