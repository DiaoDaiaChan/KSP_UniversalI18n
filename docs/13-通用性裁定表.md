# 13 · 通用性裁定表（审计「存疑」逐条结案）

> 来源：2026-10 的全量硬编码审计（`_audit/hardcode/` 五份报告）在每份报告末尾留了一节「存疑」，
> 共 **15 条**（总报告口径合并同性质项后给的是 9 条）。它们当时都判「当前不算违规」，但判据靠一句散文，
> 下一个人读不到、也不会知道自己踩到了同一个坑。
>
> 本文件的用处：**每条存疑都必须落在三处之一** —— ①被单测/门禁钉死；②被修掉；③明确裁定「不修，理由是这个」。
> 只写在报告里的结论会随时间蒸发，写成断言和裁定表不会。

## 0. 四条裁定口径（后面 15 条都按这个判）

| 口径 | 内容 | 为什么 |
|---|---|---|
| 自身身份不算 V2 | 指向**本产品**自己的目录/程序集/桶名（`GameData/UI18n/`、`UI18n-Unattributed`）不属「写死某个 mod」 | 它不是对第三方 mod 的判断、路由、归属；但**同一字符串多份副本**要消掉 |
| 平台本体名白名单 | `Squad`/`Assembly-CSharp`/`UnityEngine`/`TMPro`/`HarmonyLib` 属游戏本体与运行时 | 拦截点必须是游戏自己的出口；`Squad` 还是 KSP 官方中文本体的包名 |
| 夹具不算 | 测试/自检夹具里的 mod 名（含构造器默认值） | 夹具不是产品行为；但**默认参数**这种「读起来像产品默认值」的形态要改 |
| 草稿区不算 | `tools/_scratch/`、`_audit/` 等不被构建/CI 引用的目录 | 不是交付物；门禁 `SKIP_DIRS` 已排除 |

## 2. 三条新断言怎么跑

```bash
# ① 安装目录单源 + ② 跳过表只装框架命名空间（C# 单测，加在现有 1067 例里）
dotnet tests/UI18n.Core.Tests/bin/Debug/net10.0/UI18n.Core.Tests.dll

# ③ 自造桶名登记制（Python 门禁，进 CI gates）
python tests/hardcode/test-no-mod-hardcode.py --self-test   # 15 项
python tests/hardcode/test-no-mod-hardcode.py               # checks≈152,176 failures=0
```

## 3. 以后想加一条「这里可以有 mod 名」

按优先级从高到低：

1. **能数据化就数据化** —— 挪到 `packs/*.json`（`noise_patterns.json` / `display-names.json` / `conventions.jsonl` / `mods.json`），代码只留读取器。
2. **数据化不了就登记** —— 加进 `tests/hardcode/test-no-mod-hardcode.py` 的 `PSEUDO_PREFIX_LITERALS`（伪 mod 桶）或在测试里逐项钉死（内建表类）。
3. **实在要留在代码里** —— 行尾写 `# 硬编码豁免: <原因至少 6 字>`，只对该行生效；没有原因就不放行。
