## 0. 要解决的问题（为什么以前会漏）

用户实测反馈：更新已应用，屏幕上仍有整段英文。逐条取证后确认三个结构性来源，**都不是偶发 bug**：

1. **身份错位**：字典键 = 源文件原文的哈希；运行时渲染的是 ModuleManager 打完补丁后的合成文本。
   任何被 `@description` / `@title` 改写的文本哈希都对不上（RO/RP-1 属常态）。
2. **无度量的布尔过滤**：捕获端有一串 `return ("never", reason)` 的级联（`tools/i18n_tools/capture_ingest.py:173-219`），
   C# 侧 `src/UI18n.Core/Capture/CaptureStore.cs:41-47` 的 `_never/_filtered/_overflow/_templateSkipped` 只累加计数、不留正文。
   **判错的串永久消失，且系统里没有任何痕迹**。
3. **五条通道各自为政**：cfg / loc / IL / ConfigCache / capture 各有去重键、过滤规则、分母，
   谁也回答不了「这台机器上还剩多少英文」。

## 1. 五条决策

### D-T1 真相层是渲染出口，不是文件
「屏幕上出现过什么」只能由运行时回答。静态抽取（cfg / loc / IL / ConfigCache）降级为**预热**，
不再承担完备性。「遗漏」的正式定义变成：*渲染出口出现过、但字典里没有的串*。

### D-T2 捕获端不丢正文：过滤只决定优先级
捕获端**禁止**因「像噪声」而丢正文。允许丢弃的只有两种，且都必须留痕：
- 文本长度超过 `MaxTextLength`（默认 8000）→ 按上限截断写入，行内标 `"truncated": true`；
- 本会话写入字节数超过 `MaxSessionBytes`（默认 64 MiB）→ 停止写正文，只累加计数，日志打一次 `capture: session byte budget exhausted`。

原 `MaxEntries` / `MaxTemplateEntries` / `MaxPerCaller` 三个「丢弃型」上限**全部退役**（字段保留以免配置解析炸，
语义改为「不再限制」，doc 注释明写退役原因）。`CaptureFilter` 不再拒绝任何串，只产出 `reason` 标签。

### D-T3 一张候选表
新文件 `packs/candidates.jsonl`：**五条通道唯一的候选清单**。行 schema（固定，字段顺序固定）：

```json
{"h":"<16 hex>","s":"<归一化原文>","src":"<原文>","bucket":"candidate|template|never",
 "reason":"<none|path|logline|too-long|progress|counter|punct|identifier|already-cjk|keyref|...>",
 "channel":"cfg|loc|il|cfgcache|capture","caller":"<Type.Method 或空>","sink":"<渲染出口或空>",
 "count":<int>,"mod":"<modId 或空>","firstSeen":"<ISO8601 或空>","covered":<bool>}
```

- 去重键：`h`（`fnv1a64(normalize(s))`，与字典同口径，复用 `tools/i18n_tools/fnv.py`）。
- `covered`：该 `h` 是否已存在于 `packs/zh-cn/*.jsonl`。
- `bucket` 是**优先级**，不是「要不要留」：`candidate` > `template` > `never`。
  送翻顺序按 bucket 分层 + count 降序；`never` 依然留档（可复查、可统计、下一轮可能翻案）。
- 产物必须**确定性**（同输入同字节）：按 `bucket` 优先级 → `h` 排序输出。

### D-T4 两个覆盖率口径，验收只看后者
- **pool 覆盖率**（现有）：`packs/pool.jsonl` 静态池口径，73.46%。**保留但不再是验收口径**，因为它与玩家体感不同源。
- **render 覆盖率**（新）：`本会话渲染过的 distinct 串中，命中译文的比例`。由运行时统计并落盘
  `<KSP>/PluginData/UI18n/render-<UTC stamp>.json`，日志一行：
  `[UI18n] render coverage: hit=<n> miss=<n> distinct=<n> ratio=<0.0000>`。
  这是**唯一**对用户承诺的数字，`reports/coverage.md` 必须同时列两个口径并注明差异。

### D-T5 golden set 门禁
用户报过的每一条英文都是回归用例。`tests/golden/rendered-strings.txt` 一行一条原文（`#` 开头为注释），
`tools/i18n_tools/golden_gate.py` 断言：每一条都 **①`capture_ingest` 判为 bucket != "dropped"、②在 `packs/candidates.jsonl` 里、
③在 `packs/zh-cn/*.jsonl` 里有非空译文**。任一条失败 → exit 1。
纪律：任何过滤器/阈值改动使 golden set 变红，**改过滤器，不改 golden set**。

## 2. 已确证的既有格式（不要重新发明）

- 捕获行（`PluginData/UI18n/capture-*.jsonl`）字段：`h, n, s, sink, caller, count, firstSeen, template, reason, bucket`
  （`src/UI18n.Core/Capture/CaptureJson.cs`）。1.5 **只在末尾追加** `truncated`（省略时为 false，不写字段），不动既有字段顺序与语义。
- 字典行（`packs/zh-cn/*.jsonl`）：`{"h","n","s","t","mod"}`。
- overrides 行：`{"en","zh","note"[, "keep": true]}`。
- 人工覆盖命中即直出、不联网：`tools/i18n_tools/translate_il.py` 的 `manual = self._override(item)` 在缓存与 LLM 调用之前。
