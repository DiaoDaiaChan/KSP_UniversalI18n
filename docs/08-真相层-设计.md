# 08 · 真相层（v1.5 设计契约）

> 本文档定义 v1.5 真相层架构设计契约，统一运行时捕获、候选表与覆盖率的统计口径。
> 仓库根目录：`C:/Users/43701/Documents/github/UniversalI18n`。

## 0. 待解决的问题

用户实测反馈显示更新后界面仍存在未翻译文本，排查确认存在三个结构性成因：

1. **键值与显示内容不匹配**：词典键为原始文件英文文本的哈希，而运行时渲染的是经 ModuleManager 补丁改写后的合成文本（例如被 `@description` / `@title` 修改的文本无法直接命中）。
2. **规则过滤无正文留痕**：捕获端存在级联过滤规则（`tools/i18n_tools/capture_ingest.py`），C# 运行时（`src/UI18n.Core/Capture/CaptureStore.cs`）仅累加过滤计数而不保存正文，导致被误判的文本无法追溯与复核。
3. **数据通道统计口径分散**：cfg、loc、IL、ConfigCache、capture 五条数据通道各自分立，去重键与过滤规则不一致，缺乏统一的未翻译词条基数。

## 1. 核心架构决策

### D-T1 以渲染出口为核心真相源
屏幕显示内容由运行时实际渲染决定。静态抽取（cfg / loc / IL / ConfigCache）定位为预热基础；未翻译文本的定义为：运行时渲染出口出现、且词典中尚未收录的文本。

### D-T2 捕获端保留正文，过滤仅决定优先级
捕获端不再直接丢弃文本正文。仅允许两类边界处理且必须留痕：
- 文本长度超过 `MaxTextLength`（默认 8000）：按上限截断写入，并在行内标记 `"truncated": true`；
- 单会话写入字节数超过 `MaxSessionBytes`（默认 64 MiB）：停止写入正文并记录日志 `capture: session byte budget exhausted`。

原 `MaxEntries`、`MaxTemplateEntries`、`MaxPerCaller` 等丢弃型配置项退役（保留配置字段兼容性，内部不再强制丢弃）。`CaptureFilter` 不再丢弃数据，仅输出分类标签。

### D-T3 统一候选表（Single Candidate List）
建立统一文件 `packs/candidates.jsonl` 作为五条通道的汇聚清单。行数据结构（固定字段顺序）：

```json
{"h":"<16 hex>","s":"<归一化原文>","src":"<原文>","bucket":"candidate|template|never",
 "reason":"<none|path|logline|too-long|progress|counter|punct|identifier|already-cjk|keyref|...>",
 "channel":"cfg|loc|il|cfgcache|capture","caller":"<Type.Method 或空>","sink":"<渲染出口或空>",
 "count":<int>,"mod":"<modId 或空>","firstSeen":"<ISO8601 或空>","covered":<bool>}
```

- 去重键：`h`（`fnv1a64(normalize(s))`，与词典口径一致）。
- `covered`：指示该哈希是否已收录于 `packs/zh-cn/*.jsonl`。
- `bucket` 表示处理优先级：`candidate` > `template` > `never`。翻译批处理按优先级梯次与出现频次降序处理；`never` 档依然归档留痕，便于复查。
- 保证生成确定性（相同输入产出相同字节）：按优先级与哈希排序输出。

### D-T4 统一覆盖率评估标准
- **pool 覆盖率**：基于 `packs/pool.jsonl` 静态候选池的统计比例（参考值 73.46%），保留作为静态参考，不作为最终交付验收口径。
- **render 覆盖率**：基于实际运行会话中渲染文本的命中比例。由运行时统计并记录于 `<KSP>/PluginData/UI18n/render-<UTC stamp>.json`，日志格式如下：
  `[UI18n] render coverage: hit=<n> miss=<n> distinct=<n> ratio=<0.0000>`。
  `reports/coverage.md` 同时记录两种口径并说明分母差异。

### D-T5 回归黄金用例集门禁（Golden Gate）
将用户反馈的关键英文文本纳入回归用例集。用例清单维护于 `tests/golden/rendered-strings.txt`（每行一条文本，`#` 开头为注释）。`tools/i18n_tools/golden_gate.py` 验证三项断言：
1. `capture_ingest` 判定其 bucket != "dropped"；
2. 条目已收录于 `packs/candidates.jsonl`；
3. 在 `packs/zh-cn/*.jsonl` 中存在非空译文。
若任一项未满足则判定失败。当过滤器调整引发用例未通过时，应修正过滤策略而非修改用例集。

## 2. 既有数据格式规范

- 捕获记录行（`PluginData/UI18n/capture-*.jsonl`）字段：`h, n, s, sink, caller, count, firstSeen, template, reason, bucket`（定义于 `src/UI18n.Core/Capture/CaptureJson.cs`）。在末尾可选追加 `truncated`（默认省略），保持既有字段顺序与语义一致。
- 词典数据行（`packs/zh-cn/*.jsonl`）：`{"h","n","s","t","mod"}`。
- overrides 行：`{"en","zh","note"[, "keep": true]}`。
- 人工覆盖优先输出：`tools/i18n_tools/translate_il.py` 在缓存与模型调用前优先检查 overrides。
